# 本地素材采集

本地执行 npm run dev 后，通过 localhost 或 127.0.0.1 打开 Studio，可看到「素材采集」。生产 build 不注册该路由、不显示菜单，也不包含本地接口客户端。局域网 IP 访问不开放此功能。

在被 Git 忽略的 .env.local 中配置：

```dotenv
WALLPAPER_COLLECTOR_DIR="/绝对路径/fetch-wallpaper"
# 可选，默认优先使用采集项目的 .venv/bin/python
# WALLPAPER_COLLECTOR_PYTHON="/绝对路径/python"
```

进入采集页面时，Studio 自动启动专属 Python 桥接；停止 Studio 时关闭自己启动的桥接。同一采集项目只允许一个桥接进程，避免两个开发端口同时控制同一份批次。无需另开原来的 start.command；执行本地清理前须关闭原独立 8765 服务。原服务自定义端口暂不支持跨进程协调，应只使用一个入口管理素材。

## 操作流程

1. 采集设置中选平台、图源、页码、设备和清晰度，启用自动分批。
2. 待上传批次选择「送到图片上传」，自动逐张读取、核验原图哈希并进入现有 AI 分析。导入本身不会写入 GitHub。
3. 审核分类和描述，确认后手动上传。原始身份随 AI 改名和图片压缩保留。
4. 可在批次的「查看图片」中预览并删除单张或多选图片；从上传列表移除本批图片也会删除对应本地原图、硬链接及清单条目，不保留已删除条目。剩余图片与元数据全部成功提交后自动清理本批。回传中断可在采集页重试。
5. 不通过采集入口导入、或全部图片都不需要时，可以直接在采集页点击「清理本地」，确认后删除整批本地文件，无需上传核验。删除接口未成功时上传页会保留该项，避免只清掉界面却没删除文件。

「上传核验完成」不等于「网站发布完成」。网站继续通过现有发布工作流部署。

源文件和上传文件的 SHA-256 分开记录，压缩不会丢失原图身份。仅清理指定批次内原图、硬链接和缩略缓存，目录为空才移除；未删除素材的来源记录和正常上传完成的批次记录保留；单张删除从批次与当前素材清单彻底剔除，不新增删除历史。自动清理遇到图片变化、远端核验失败、保留图片未完成上传或并发采集时停止；手动清理保留本地路径和哈希检查，允许清理未上传批次。GitHub Token 仅用于当前核验请求，不保存在 Python 数据库或回执队列。

## 自动分批

同图源、同设备再次采集时，优先补满首批计划日期及之后、尚未导入审核或上传的未满批次，再从已有最后计划日期的下一天继续排期。已导入审核、已有上传回执、已授权自动清理及历史批次不追加图片。历史超过目标数量的批次保持原样。旧有重复日期批次不会自动重排或迁移。

## 本次边界

Python 采集代码仍使用配置目录中的现有项目；没有复制进 Studio 仓库。后续独立服务器部署需另加服务身份认证、用户与目录隔离、持久存储和运维管理。当前本机桥接不能直接暴露公网。

验证命令：

```sh
npx vitest run src
node --test server/local-collector/plugin.test.mjs
WALLPAPER_COLLECTOR_TEST_DIR="/绝对路径/fetch-wallpaper" PYTHONDONTWRITEBYTECODE=1 "/绝对路径/fetch-wallpaper/.venv/bin/python" -m unittest discover -s server/local-collector -p test_bridge.py
npm run build
npm run check:client-secrets
```

批次数量与预览每次读取都会检查本地原图和批次目录链接。已经在 Finder 删除的图片不会继续算入数量或导入；执行后续导入、上传回传时会清理它的残余链接。网页没有操作系统文件监听，打开或刷新列表/预览时更新，并随页面轮询刷新。
